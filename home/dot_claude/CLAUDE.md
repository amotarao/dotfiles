## 一時ファイル

スクリプトや md などの一時ファイルを用意するとき、プロジェクトの `.local` ディレクトリを利用すること  
`.local/{YYYY-MM-DD}_{作業内容}/{FILE}` とすると分かりやすい  
worktree 作業中に一時ファイルを作る必要がある場合も、メインディレクトリの `.local` ディレクトリを利用すること

## git 操作

### 基本事項

- `git -C` や `git --git-dir` は禁止。`cd` 先で `-C` なしでコマンドを実行すること

### ブランチを切っての作業

ブランチを切って新しい作業する際、基本的には通常の checkout をし、指定があったときのみ git worktree 方式を利用して作業すること

### worktree で作業する場合

- `.local/worktree` が存在しない場合のみディレクトリを作成
  - 通常はスキップし、次のステップでディレクトリがないなどのエラーが発生したときのみ実行
  - `mkdir -p .local/worktree`
- worktree を作成 (存在しないとき)
  - `git worktree add -b {BRANCH_NAME} .local/worktree/{BRANCH_NAME (/ は _ などに置き換え)} {ベースブランチ (通常はデフォルトブランチ)}`
  - 指定したとき以外は、デフォルトブランチをベースにすること
- worktree に `cd`
  - 作業開始時に1回だけ実行
  - `cd .local/worktree/{BRANCH_NAME (/ は _ などに置き換え)}`
- 居場所の確認
  - worktree での作業時、各コマンド実行の前後で実行し、居場所を迷わないようにすること
  - また、他のコマンドと同時の実行 (&&) は禁止
  - pwd で居場所が確認できたら、`cd PATH && git add` のようなことは、`git add` だけで済むはずので禁止
  - `pwd`

`git worktree add` 時に `fatal: bad object 0000000000000000000000000000000000000000` というメッセージが出ても正常なので無視すること

pnpm i や npm i など、必要なセットアップを実行  
セットアップは worktree に `cd` した直後、ファイル編集や最初の commit より**前に**必ず行うこと  
husky の hook 実体 (`.husky/_`) は gitignore 対象で `pnpm i` の `prepare` が生成するため、それより前の commit は pre-commit (lint-staged / oxfmt) が警告なしに素通りする  
cd は worktree の切り替え時以外は基本利用しないこと

### worktree で作業している場合の禁止事項

- worktree のディレクトリに移動する際に利用する `cd` を、他のコマンドと同時に (`&&` や `||`) 実行すること

### PR や Issues の本文を作成/更新する場合

`--body "$(cat <<'EOF' ... EOF)"` のヒアドキュメント形式は使用禁止  
追加の承認を求められることが多いため  
代わりに以下の手順で本文を渡すこと:

1. `Write` ツールで一時ファイルに本文を作成
2. `--body-file <パス>` オプションで渡す

対象コマンド: `gh pr create`, `gh pr edit`, `gh issue create`, `gh issue edit`, `gh issue comment`, `gh pr comment`, `gh pr review` 等の、ファイルパスを渡せるコマンド

### コミット

常に変更ファイルを確認したのちのコミットすること  
あなたは無関係なファイルをステージングしたり、`git reset --soft` の後、無関係なステージングファイルが残ったまま commit したりしてミスを犯すことがあり、それを防止するためです

## pnpm-lock.yaml のコンフリクト解消

`pnpm install` で解消可能  
`pnpm-lock.yaml` の再生成などはしないこと

## Backlog 操作

許可なく編集やコメントをしないこと

## パスを扱うコマンド操作

`git add`, `ls` など、パスを扱うすべてのコマンド操作において、ディレクトリやファイル名に `()` や `[]` が含まれることもあるため、必ず `""` で囲うこと

## cd 操作

cd は worktree の切り替え時以外は基本利用しないこと

## コミット規則

### コミット粒度規則

- **適切な分割**: すべての変更ファイルをまとめてコミットするのではなく、変更内容ごとに適切な粒度で複数コミットに分割する
  - 機能追加、バグ修正、リファクタリング、ドキュメント更新などは個別にコミット
  - 関連する変更のみをグループ化し、論理的な単位でコミットを作成
  - コミットメッセージは変更内容を明確に示すものにする
